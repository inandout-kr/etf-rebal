# ETF 리밸런싱 사전 진행 추정: 데이터 수집 명세

작성일: 2026-09-11. 대상은 국내 주식 ETF의 정기·수시 지수 변경이다. 공개 일별 PDF와 오차가 있는 종목별 30분 수급을 사용하며, ETF 계좌별 실제 체결자료는 확보되지 않은 것으로 한다.

이 문서의 수집 주기·허용 지연·과거 이력 길이는 **제안하는 운영 목표**다. 거래소 규정이나 공급자가 보장하는 사양, 통계적 정확성이 검증된 기준이 아니다. 실제 제공 주기와 지연은 계약·샘플로 확인한다.

## 1. 목적별 최소 데이터

| 원하는 결과 | 최소 데이터 |
|---|---|
| 오늘 장중 바스켓 진행 신호 | 고정된 잔여 목표수량·기준가격 + 대상 종목 누적 수급 + 동일 시간대 배경수급·오차폭 + 정보 입수시각 |
| 며칠 전부터의 PDF 구성 전환 | 공지 전 기준 PDF부터 매일 PDF 수량 + CU 좌수 + ETF 발행좌수 + 기업행동 |
| 조건부 잔여 수요 | 위 진행 신호 + ETF 귀속률 시나리오. 귀속률은 별도 가정이며 공개 수급만으로 식별되지 않음 |
| 실제 ETF 시장 체결량 | ETF별 체결원장 또는 실제 보유변동과 현물 설정·환매 등 비시장 이동의 완전한 조정. 현재 확보 범위에서 제외 |

현재 수급 계산기가 최신 PDF 대비 잔여 수요를 이미 만들었다면, 과거 PDF 구성 전환분을 그 잔여 수요에서 다시 차감하지 않는다. 한 ETF의 PDF만으로 같은 지수의 다른 ETF 보유변동을 확정하지 않는다.

A·B는 기존 프로젝트의 이벤트·수급 산출을 재사용할 수 있다. E의 구성수량이 있어도 F의 CU·발행좌수와 G의 기업행동 확인이 없으면 ETF 전체 주식 수로 환산한 전환량을 확정하지 않는다.

PDF에는 실제 보유원장과 다른 설정·환매 바스켓이 나타날 수 있다. KRX 안내서는 PDF가 일별로 공시되고 해당 구성수량에 실시간 가격을 적용해 직접방식 iNAV를 산출한다고 설명한다. 일별 PDF와 장중 체결자료를 구별한다. [KRX ETF 안내서, 인쇄 28~29쪽](https://pdf.krx.co.kr/ebook_new/access/ecatalogt.jsp?Dir=23&callmode=normal&catimage=&eclang=ko&start=29&um=s), [KRX ETF FAQ](https://m.krx.co.kr/contents/06/0609/060901/JHPETP060901M01.jsp).

20일·60~120일은 수집 계획을 위한 시작 범위다. 신뢰구간의 보장 표본 수가 아니다. 유동성별·시간대별 자료와 독립적인 이벤트 수가 부족하면 더 긴 이력이 필요하다. 데이터 상품 정의·시장 범위가 바뀐 구간은 같은 모집단으로 무조건 합치지 않는다.

**오차 보정 시 지켜야 할 두 가지:**

1. 13:00 추정 수급의 오차를 15:30 최종 수급과의 차이로 계산하지 않는다. 오후에 실제 거래가 추가되므로 같은 13:00 기준의 수정/확정 수급이 필요하다. 동일 집계시각 정답이 없으면 그 부분은 미검증으로 남긴다.
2. 다음날 PDF로 전일 하루의 구성 변화를 볼 수 있어도 전일 장중 체결과 종가 체결을 나눌 수 없다. 이를 장중 집행률의 정답으로 쓰지 않는다.

## 4. 실시간성 상세

기본 스냅샷은 09:30, 10:00, 10:30, …, 15:00의 동일 기준 누적치로 제안한다. 최종 거래일에는 가능하면 15:10·15:15·15:19 또는 15:20까지의 체결 수급 스냅샷을 추가 요청한다. 추가 수집이 불가능하면 15:00 이후 구간은 미관측으로 남긴다.

| 용도 | 제안 주기 | 제안 수신 지연 | 해석 |
|---|---|---|---|
| 장중 중간 점검 | 30분 | 집계 종료 후 5분 이내 | 사용자가 제공 가능한 데이터로 시작할 수 있는 수준 |
| 종가 직전 잔여 수급 점검 | 가능하면 1~5분, 특히 14:30 이후 | 1분 이내 목표 | 30분 데이터가 못 보는 마지막 집행 구간을 줄임 |
| PDF 구성 전환 | 일별 | 공개 후, 해당일 분석 전에 확보 | 실시간 PDF를 요구하지 않음. 늦으면 기준일이 오래됐음을 표시 |
| 사후 검증 | 일별·공시별 | 실제 확정·공개 이후 | 과거 의사결정 입력과 분리 |

예: **14:30까지 수급을 14:33에 수신**하면 집계 주기 30분, 공급 지연 3분이다. 14:59에 보는 이 수급의 정보 나이는 29분이다. 프로그램을 매초 새로고침해도 수급 기준시각은 새로워지지 않는다.

`정보 나이 = 의사결정시각 − 수급 집계시각`과 `공급 지연 = 실제 수신시각 − 수급 집계시각`을 따로 기록한다. 현재 코드는 정보 나이를 출력하지만 5분/10분 지연 차단 규칙은 자동 시행하지 않는다. 위 기준은 추가 운영 정책 제안이다.

최종 거래일 15:30 누적 수급에는 종가 체결이 들어갈 수 있으므로 현재 사전집행 모형의 관측 입력에서 제외한다. 15:20 체결 기준 자료를 15:22에 받았다면 15:22 이후 판단에만 사용한다. 조기 종료·개장 변경 등 특수 일정은 해당일 캘린더를 확인한다.

NXT에는 별도의 프리·메인·애프터 및 종가매매 세션이 있으므로 KRX만 포함한 데이터와 통합 데이터는 관측 범위가 다르다. **시장·세션을 모르면 누적 시작을 09:00으로 단정하지 않는다.** NXT 대상 거래를 빠뜨렸다면 이를 0으로 간주하지 않고 해당 시장이 미관측임을 표시한다. [NXT 공식 거래제도](https://www.nextrade.co.kr/menu/transactionSys.do).

## 5. 장중 수급 공급자에게 요청할 필드

매 스냅샷은 대상 종목 전체를 포함한다. 기관 합계 또는 프로그램 중 하나의 일관된 채널이 최소 요건이며, 투신·금융투자·연기금 등 하위 분류가 있으면 각각 별도 보존한다. 투자자 분류는 ETF 계좌 식별자가 아니다.

| 필드 | 필수 여부 | 의미 |
|---|---|---|
| 거래일 | 필수 | 누적치가 귀속되는 거래일 |
| 종목코드 | 필수 | 문자열. 선행 0과 영문 포함 코드를 보존 |
| 수급 집계 종료시각 | 필수 | 실제 어느 시점까지 체결을 반영했는지, Asia/Seoul 또는 +09:00 |
| 실제 수신시각 | 필수 | 우리가 해당 버전을 실제로 받은 시각. 과거값을 임의 소급하지 않음 |
| 공급자 발표시각 | 가능하면 | 공급 지연과 수집 지연을 구별 |
| 누적 시작시각·범위 | 필수 | 예: 09:00부터 누적. 30분 구간값이라면 별도 표기 |
| 수급 분류·공급자 | 필수 | 기관합계/투신/금융투자/프로그램 등 원본 분류, 공급 데이터 상품 식별자 |
| 시장·세션 범위 | 필수 | KRX / NXT / 중복 제거 통합, 시가·연속매매·시간외·대량매매 포함 여부 |
| 누적 순매수수량 | 현 코어 필수 | 주, 매수＋/매도－. 금액은 현재 코어가 자동 처리하지 않음 |
| 누적 매수·매도수량 | 권장 | 순수량의 검증 및 매수·매도 방향별 자료 |
| 누적 순매수금액·매수금액·매도금액 | 권장 | 원 단위 권장. 억원 등 원단위를 함께 명시 |
| 잠정/수정/확정 상태·수정번호 | 필수 또는 수집기가 생성 | 잠정치는 그대로 보존하고 정정본을 추가 |
| 결측·거래정지·품질 표시 | 필수 | 누락과 실제 0을 구분. 오래된 수치의 재전송도 표시 |

누적 순매수금액을 현재가로 나눈 값은 정확한 누적 순매수수량이 아니다. 매수·매도 평균가격이 다를 수 있기 때문이다. 수량 공급이 우선이다. **금액만 가능하면 금액 기준 모형 또는 별도 환산 어댑터를 추가하고, 환산오차를 반영해야 한다. 현재 구현에는 그 자동 어댑터가 없다.**

기관 순매수와 프로그램 순매수는 겹칠 수 있어 합산하지 않는다. KRX·NXT 통합 데이터가 이미 제공되면 개별시장 데이터를 다시 더하지 않는다. 공급자가 매수/매도 체결 방향으로 추정한 수급인지 투자자 분류 통계인지도 확인한다.

## 6. ETF/PDF 공급자에게 요청할 필드

- ETF 코드·상품명·추종지수·상품유형, 구성종목 코드·자산유형·원단위.
- 전체 PDF 원본, 종목별 1 CU당 수량, CU의 ETF 좌수, 현금·파생 관련 항목.
- ETF 발행좌수·NAV·AUM 및 각각의 기준시점. 발행좌수 순변화를 실제 현물 설정량이라고 단정하지 않는다.
- PDF 적용일과 구성/평가 기준시점, 공급자 공표시각과 실제 수신시각, 원본 버전·완전성.
- 기준시점이 확인되지 않으면 ‘PDF 날짜 = 전일 15:30 보유량’으로 자동 치환하지 않는다. PDF 바스켓과 실제 보유자료를 구별한다.
- CU 변경, 주식/ETF 분할·합병 등 기업행동의 효력일과 조정계수. 비조정 수량에 조정가격을 무심코 섞지 않는다.

공개 원본의 현금·파생 항목을 보존한 뒤 주식 분석 대상만 구분한다. 파생계약 수량을 주식 수로 집계하지 않는다. 현재 PDF 비교 함수에는 동일 기준으로 정규화되고 전체 주식 목록임이 확인된 수량을 공급해야 한다.

## 8. 현재 구현과 추가 수집/구현의 경계

이미 구현된 부분은 기존 잔여수급의 수량 고정, 최신 가용 누적 스냅샷 선택, 배경·오차를 입력받는 바스켓 추정, 귀속률 시나리오, PDF 수량 정규화다. 새 공급자 API 연결·자동 수집·배경수급 학습·공급 오차 보정·금액 데이터 변환·시장 범위 검증·지연 경보는 별도 작업이다.

현 코어는 종목별 `net_buy_shares`, `background_shares`, 양수 `error_bound_shares`가 모두 있어야 해당 종목을 사용한다. 배경수급과 오차폭은 **공급자에게 반드시 받는 원천자료가 아니라 H~K를 바탕으로 내부에서 산출하는 값**이다. 이력이 없을 때는 명시적인 임시 가정임을 표시해야 한다.

현 코어는 비영 수요 종목 최소 3개와 매수·매도 양쪽 지원을 요구한다. 한쪽만 있는 수시 이벤트는 현재 공통 바스켓 모형에서 추정하지 못한다. 커버리지는 출력하지만 최소 커버리지 비율이나 자동 신선도 차단 기준은 아직 구현되어 있지 않다.

매 스냅샷 전체 대상 종목을 보내야 한다. 새 스냅샷에서 빠진 종목은 이전값을 자동 이월하지 않는다. 누적치는 더하지 않고 교체한다. 장중 공지로 관측 시작을 바꾸는 경우 해당 시작시점의 누적 기준값이 필요하며, 정확한 값이 없으면 처음 확보한 이후 스냅샷부터 새 구간을 시작한다.

### 공급자 문의용 요청 요약

1. 대상 전 종목의 30분 누적 투자자/프로그램 **순매수수량** 제공 여부. 수량이 없으면 금액 원본의 매수·매도 구분과 단위.
2. 집계시각·발표시각·실제 지연, 잠정치 수정 방식, 동일 집계시각의 수정/확정 이력 제공 여부.
3. KRX/NXT/통합 여부, 세션·대량매매 포함 범위, 누적 시작시각, 데이터 분류 정의.
4. 동일 형식 과거 60~120거래일 및 이후 일별 누적 저장 가능 여부.
5. ETF별 일별 PDF 수량, CU 좌수, 발행좌수·NAV·AUM, 기업행동 및 과거 원본 제공 여부.
6. 14:30 이후 추가 스냅샷이나 15:20 이전 마지막 체결 수급 제공 가능 여부.
