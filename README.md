# ETF·BM 편출입 트래커 (etf-rebal)

국내 상장 ETF 중 순자산 상위 종목이 추종하는 기초지수(BM)의 **공식 방법론**을 기준으로,
정기변경·수시변경 편출입 예상 종목과 일정을 계산해 정적 웹페이지로 제공합니다.

- 사이트: https://inandout-kr.github.io/etf-rebal/
- 방법론 원문: `docs/methodology/` (KRX 지수산출방법 게시 PDF, FnGuide Methodology Book, MSCI GIMI)

같은 시세 관측값에서 GICS와 KRICS의 심사대상을 각각 구성하고 A/B 해석을 비교합니다. KOSDAQ 150의 300위 초과 재량 제외 적용/미적용은 A/B와 독립적인 선택입니다. 공식 미확인 분류·FFR·CAP·시행일은 HOLD로 유지하며, 비교 결과를 거래소의 확정 편출입으로 표시하지 않습니다. 수급 입력 형식은 [입력 계약](docs/flow_input_contract.md)을 참고합니다.

## 구성

| 파일 | 역할 |
|---|---|
| `fetch_market.py` | 네이버(유니버스·시총), 다음(일별 종가·거래대금·상장주식수·상장일·WICS), WISE(섹터) 수집 → `data/market.sqlite` |
| `fetch_gics.py` | KRX 인덱스 사이트 공식 GICS 산업분류(산업별 종목현황, 24개 산업그룹) 수집 → `stock.gics_ig/gics_sec` |
| `fetch_holdings.py` | wisereport CU_data 로 프록시 ETF(KODEX 200 등 32종) 구성종목 수집 → `data/holdings.json` |
| `analyze.py` | KOSPI 200 / KOSDAQ 150 / KOSPI 100 정기변경 시뮬레이션, FnGuide TOP-N, 캡 트리거, 신규상장 특례, MSCI 후보 → `data/analysis.json` |
| `rebal_flow.py` / `flow_engine.py` | KRX 반도체 9월 정기변경 및 남은 정기변경 전체의 종목별 패시브 매수/매도 추정 (공식 가중·캡 규칙) |
| `backtest_june.py` | 2026년 6월 정기변경(KRX 5/22 공표)을 같은 로직으로 재현해 정답과 비교 → `data/backtest_june.json` |
| `archive.py` | 매매일(적용일 전 영업일)이 되면 그날 아침 예측을 `data/history/`에 동결, 매매 후 프록시 ETF PDF로 실제 비중변화·편출입을 대조 → 히스토리 탭 |
| `calendar_events.py` | 선물만기·심사기준일·정기변경일 등 일정 계산 (KRX 휴장일 내장) |
| `methodology_kb.py` | 지수별 공식 방법론 요약 지식베이스 → `data/methodology.json` |
| `build_site.py` + `template.html` | 정적 페이지 빌드 → `dist/` |
| `update.ps1` / `deploy_github.ps1` | 일일 갱신·gh-pages 배포 |

## 갱신과 배포

```powershell
.\update.ps1            # 기존 수집·분석·빌드·배포 경로
.\update.ps1 -NoDeploy  # 배포 제외
```

KRICS 비교 입력은 2026-10-23 기준의 고정 자료입니다. 이후 시세 기준일이 달라지면 KRICS 비교는 HOLD로 남고 기존 GICS 계산은 계속됩니다. 새 분류표는 출처·기준일·전체 행 검증 후 교체해야 합니다.

## 검증

```powershell
python -B -m unittest discover -s tests -p "test_*.py"
node tests/test_revision_ui.js
node tests/test_table_sort.js
```

예약작업 테스트는 임시 fixture와 배포 stub을 사용합니다. 실제 예약 실행이나 네트워크 배포를 호출하지 않습니다.

HOLD인 수급은 0원이나 빈 예측으로 히스토리에 저장하지 않습니다. 일별 수급 변화도 양쪽의 계산 가능한 이벤트와 HOLD 범위가 같고 값이 알려진 경우에만 비교합니다.

## 주요 가정·한계

- KOSPI 200·KOSDAQ 150은 같은 시세 관측값에서 **기존 GICS 기준 / KRICS-A / KRICS-B**를 비교합니다. KRICS는 GICS 분류 유무와 독립적으로 적격 후보를 구성하므로 심사대상 수가 다를 수 있습니다. KOSDAQ 150은 각 분류에 300위 초과 재량 제외 적용/미적용 두 정책을 함께 저장합니다. KRICS-A는1차선정 통과 AND 신규 순위 버퍼, KRICS-B는1차선정과 별개로 유동성 충족 AND 신규 순위 버퍼를 적용하는 해석 민감도입니다. 개정방법론 본문 시행일이 없어 `effective_date_status=HOLD`이며, 계산이 가능하다는 `ready`와 시행일 확인은 별개입니다. 입력 검증이 부족한 지수는 계산도 HOLD로 남기고 임의 분류로 채우지 않습니다.
- 기존 기준은 GICS 분류(미분류 종목에 기존 섹터 ETF·WICS 보완)를 사용하고, KRICS-A·B는 모두 사용자가 정리해 공유한 같은 KRICS 매핑을 사용합니다. KOSPI 826개와 KOSDAQ 1,733개의 사용자 제공 분류표 추출본을 사용합니다. 원본 통합문서는 공개하지 않으며, 출처·누락·중복·코드·9개 산업군·기준일 검증이 필요합니다. 지수 선정 결과는 KRX 공식 공표가 아닙니다.
- 공유 개정방법론의 KOSPI 200·KOSDAQ 150·KOSPI 100/50은 예비종목 별도 선정과 일반 수시 예비 자동충원을 하지 않으며, 신규상장 특례 편입 때 기존 최소종목을 자동제외하지 않습니다. **정기심사 대형주 특례(대표지수 6.4.4)의 최소종목 제외는 유지**합니다. 비구성법인에 피흡수합병되면 합병법인으로 교체하고, 구성간 흡수합병은 피흡수법인을 제외하며 합병신주를 반영합니다.
- 예비 폐지를 모든 지수에 적용하지 않습니다. 코스닥 TOP10/15·KRX TOP10 계열·코스피200 금융고배당 TOP10은 해당 방법론의 예비 규칙이 남아 있습니다. 이번 24개 PDF 중 기존 지원과 연계된 문서는6개이며 나머지18개 검토가 신규 계산 구현을 뜻하지 않습니다.
- KOSPI 100/50은 P01 p3 §5의 **30% CAP**을 적용합니다. 유동주식비율(FIF)과 CAP Factor는 다른 요소이며, 중대형 TMI 유니버스의 누적커버리지 계산에 쓰는10% cap과 최종 KRX 섹터지수의20% cap도 구분합니다. 코스닥 TOP15는 단독 본문의 풀시총과 개정안의 유동시총 기준이 충돌하여 공식 해석 전 HOLD로 남깁니다.
- 과거 정기변경 재현 성적은 `data/backtest_june.json`에서 확인합니다. 현재 분류·구성종목에서 과거 상태를 역산하므로 당시 정보를 그대로 동결한 사전 예측 검증과는 차이가 있습니다. 기존 GICS 성적을 KRICS 개정 시나리오 검증 성적으로 표시하지 않습니다.
- 관리종목·투자주의환기종목·정리매매종목·유동주식비율 10% 미만 요건은 데이터가 없어 미반영입니다.
- 유동비율(FIF)은 KODEX 200·KODEX 코스닥150·TIGER MSCI Korea ETF 비중에서 역산한 추정치입니다.
- 심사대상기간이 진행 중이면(예: 12월 정기변경은 5월~10월) 현재까지의 누적 평균으로 계산한 "중간 집계"입니다.
- 신규상장 6개월 요건은 달력상 월 단위로 판정합니다. 인프라 관련 일반 사업회사를 이름만으로 제외하지 않고, 확인된 인프라투자회사 유형을 제외합니다.
- 합병·분할 후 심사기간 재산정은 공식 공시로 확인해 등록한 기업이벤트에만 적용합니다. 해당 종목의 화면에 실제 집계기간을 표시하며, 모든 기업이벤트를 자동 수집·검증한 자료는 아닙니다.
- KOSDAQ 150은 일평균시총이 코스닥 보통주 300위 밖인 종목을 제외할 수 있다는 재량 조항의 적용/미적용을 비교합니다. 기본 표시는 적용 정책이며 A/B 신규 해석과 독립적으로 전환합니다. 일반 선정 규칙만 적용한 편출입 수와 차이, 제외·대체 종목 및 전체 시총순위를 함께 표시합니다. 거래소의 공식 확정 결과는 아닙니다.
- 두 지수의 최근 15매매일 평균시총 상위 50위 특례는 최근 15매매일 관측이 완료된 전체 심사대상 종목을 비교해 미선정 후보를 별도 표시합니다. 위원회 판단이 필요한 후보를 자동 편입으로 확정하지 않습니다.
- 부적합 종목 판정 등 KRX 주가지수운영위원회의 개별 정성 판단은 반영되지 않습니다.
- 매매가 끝난 정기변경은 활성 탭에서 빠지고 히스토리 탭으로 이동합니다. 스냅샷 파일(`data/history/*.json`)은 이후 갱신에서 덮어쓰지 않으며, 실제 결과는 ETF 실물 PDF 기준이라 지수 실제 비중과는 현금·선물·추적오차만큼 차이가 납니다.

## 화면 사용

- 표의 열 제목을 클릭하면 오름차순·내림차순으로 정렬됩니다. 선택한 방향은 열 제목에 표시되며, 키보드로 열 제목에 이동한 뒤 Enter 또는 Space로도 정렬할 수 있습니다.
- 금액·비율·날짜는 해당 값 기준으로 비교하고, 결측값은 정렬 방향과 관계없이 마지막에 표시합니다.
- 대시보드의 종목명에서 종목별 분석으로 이동할 수 있습니다. 종목코드의 외부 시세 링크는 별도로 유지합니다.
- ‘오늘 달라진 것’은 직전 데이터 기준일의 일별 스냅샷과 비교합니다. 처음 실행할 때는 기준 스냅샷만 저장하며 변화량을 임의로 만들지 않습니다.
- KRX 반도체 전용 상단 탭은 제공하지 않습니다. ETF·방법론, 공통 수급과 히스토리에서 기존 자료를 조회하며, 이전 `#semi` 주소는 전체 리밸 플로우로 연결됩니다.

## 데이터 기준과 검증

- 기간 평균과 최근 20거래일 평균 거래대금은 한국시간 기준 거래가 완료된 날의 데이터만 사용합니다. 거래정지 등으로 거래대금이 0인 정상 완료일을 일괄 제외하지 않습니다.
- 수집 실패 시 마지막 정상 데이터를 보존하고, 데이터의 기준일과 대체값 사용 여부를 화면에 표시합니다.
- 현재 화면·향후 심사는 마지막 검증된 현재 유니버스와 종목별 완료 가격일을 사용합니다. 가격 기준일 당시의 상장 유니버스를 재구성한 자료가 아닙니다. 이탈 종목의 과거 기록은 보존하며, 활성 종목의 기준일 가격 누락은 명시하고 보유종목의 수급 계산을 보류합니다.
- 출처·관측시각·값이 검증되지 않은 환율로 MSCI를 계산하지 않습니다. MSCI만 보류하며 국내 원화 계산은 계속할 수 있습니다. 검증된 이전 환율은 원래 관측시각을 유지합니다.
- 정기변경 날짜는 공통 일정 규칙에서 계산합니다. 공식 공표가 확인되지 않은 날짜와 휴장일 정보의 지원 범위 밖인 일정은 확정 일정으로 취급하지 않습니다.
- 빌드 전에 필수 데이터, 기준일, 구성 수, 비중 합계와 수급 계산의 유효성을 검사합니다.
- 일별 비교 스냅샷은 `data/daily_snapshots/`에, 기존 정기변경 예측 스냅샷은 `data/history/`에 각각 보관합니다.

## KOSDAQ 150 입력·시나리오 보존

- CHECK 유동시총 결측은 공식 결격 판정으로 간주하지 않습니다. 외부 보고서의 CHECK 제외 가정·평균값을 재현한 결과는 보조 비교이며 운영 입력을 13/13에 맞추지 않습니다. 평균시총 원장은 종가·해당일 상장주식수·기업이벤트와 별도로 검증해야 합니다.
- KRICS에서 복원된 GICS 미분류 종목과 원시 관측 누락 목록을 화면에 구분합니다. 입력이 없는 종목의 평균시총·거래대금을 생성하지 않습니다.
- `flows.events`와 전체 수급 합계는 기본 GICS·재량 적용 정책을 한 번만 반영합니다. KQ 이벤트의 `scenario_flows`는 `GICS:applied`, `GICS:not_applied`, `A:applied`, `A:not_applied`, `B:applied`, `B:not_applied` 키로 개별 저장하며 대안끼리 합산하지 않습니다. KRICS 수급은 기존 공식 입력 HOLD를 유지합니다.
- 일별 스냅샷은 시나리오별 편출입을 같은 키로 보존합니다. 같은 거래일의 원본 파일은 덮어쓰지 않고 계산 내용이 달라진 경우에만 `daily_snapshots/revisions/`에 추가합니다. 생성시각만 바뀐 재빌드는 중복 revision을 만들지 않습니다.
- 정기변경 이력은 한 회차 안에서 각 정책의 키를 구분합니다. 금액 예측 HOLD는 별도 사유만 보관하며 0원 예측·적중률로 저장하지 않습니다. 이미 동결된 과거 회차는 일괄 재작성하지 않습니다.
